# Επισκόπηση για το τμήμα πληροφορικής

Το έγγραφο απευθύνεται στην ομάδα που θα αξιολογήσει και θα φιλοξενήσει το σύστημα. Απαντά στα πρώτα ερωτήματα που τίθενται συνήθως: τι ακριβώς εγκαθίσταται, τι χρειάζεται από την υποδομή, τι λειτουργικές υποχρεώσεις δημιουργεί, και πού βρίσκεται η αναλυτική τεκμηρίωση.

---

## 1. Τι είναι

Σύστημα ιχνηλασιμότητας βεντουζών (vacuum pads). Παρακολουθεί κάθε εξάρτημα μέσω σειριακού αριθμού/QR καθώς μετακινείται ανάμεσα σε ράφια, μηχανήματα και επισκευές, κρατώντας πλήρες ιστορικό κινήσεων, φωτογραφίες βλαβών και αναφορές.

Αποτελείται από τρία μέρη:

| Μέρος | Τεχνολογία | Πού τρέχει |
|---|---|---|
| API | NestJS (Node.js 22) | Container |
| Περιβάλλον διαχείρισης (web) | React, σερβιρισμένο από nginx | Container |
| Εφαρμογή χειριστή | Flutter / Android | Στις συσκευές, ως APK |

Μαζί τους εγκαθίστανται PostgreSQL 16 (δεδομένα) και MinIO (φωτογραφίες), επίσης σε containers.

---

## 2. Τι χρειάζεται από την υποδομή

- **Έναν διακομιστή με Docker και Docker Compose.** Linux ή Windows με Docker Desktop.
- **Reverse proxy για HTTPS.** Το σύστημα δεν τερματίζει το ίδιο TLS· περιμένει να το αναλάβει δική σας υποδομή.
- **Δύο ελεύθερες θύρες loopback**, εξ ορισμού `3000` (API) και `8080` (διαχείριση). Παραμετροποιούνται.
- **Χώρο για αντίγραφα ασφαλείας**, κατά προτίμηση εκτός του μηχανήματος που τρέχει την εφαρμογή.

Δεν απαιτείται καμία εξωτερική υπηρεσία. Το σύστημα λειτουργεί πλήρως εντός του δικτύου σας και δεν επικοινωνεί με τρίτους.

---

## 3. Δικτυακή έκθεση

Η PostgreSQL και το MinIO **δεν δημοσιεύουν καμία θύρα**· υπάρχουν μόνο στο εσωτερικό δίκτυο του Docker. Το API και η διαχείριση δένονται στο `127.0.0.1`, ώστε να αποφασίζετε εσείς τι εκτίθεται και πώς.

Κάθε endpoint του API απαιτεί συνδεδεμένο χρήστη· εξαιρούνται μόνο δύο endpoints ελέγχου υγείας, που επιστρέφουν κατάσταση λειτουργίας και τίποτα άλλο.

Αναλυτικά στο [`ARCHITECTURE.md`](ARCHITECTURE.md), και για την αξιολόγηση ασφαλείας στον ξεχωριστό φάκελο τεχνικής αξιολόγησης.

---

## 4. Σειρά εγκατάστασης

1. Κλωνοποίηση του αποθετηρίου στον διακομιστή.
2. Εκτέλεση του `./scripts/init-env.sh` (ή `.\scripts\init-env.ps1` σε Windows). Παράγει το αρχείο ρυθμίσεων με έτοιμα μυστικά και ρωτά μόνο τις δύο δημόσιες διευθύνσεις.
3. Εκκίνηση των υπηρεσιών με Docker Compose.
4. Δημιουργία του πρώτου διαχειριστή. **Χωρίς αυτό δεν μπορεί να συνδεθεί κανείς** — σε νέα εγκατάσταση κανένας λογαριασμός δεν έχει κωδικό.
5. Τοποθέτηση του reverse proxy για HTTPS.
6. Εγκατάσταση του APK στις συσκευές των χειριστών.

Τα βήματα 1 έως 5 περιγράφονται ως αριθμημένα βήματα στο `README.md`. Το βήμα 4 αναλυτικά στο [`USER_MANAGEMENT.md`](USER_MANAGEMENT.md).

Το αρχείο ρυθμίσεων που παράγεται στο βήμα 2 περιέχει τον κωδικό της βάσης και το κλειδί υπογραφής των συνεδριών. **Χρειάζεται αντίγραφο σε ασφαλές σημείο**: αν χαθεί, η εφαρμογή δεν μπορεί να προσπελάσει τα δεδομένα της.

## 5. Λειτουργικές υποχρεώσεις

Όσα δεν καλύπτει το ίδιο το σύστημα και χρειάζεται να αποφασιστούν:

| Θέμα | Τι χρειάζεται |
|---|---|
| HTTPS | Reverse proxy μπροστά από διαχείριση και API |
| Φύλαξη μυστικών | Το αρχείο ρυθμίσεων στο σύστημα διαχείρισης μυστικών σας |
| Αντίγραφα ασφαλείας | Χρονοπρογραμματισμός των έτοιμων scripts και χώρος αποθήκευσης |
| Λογαριασμοί | Ποιος λαμβάνει ρόλο διαχειριστή |
| Παρακολούθηση | Έλεγχοι υγείας, επανεκκινήσεις containers, χώρος δίσκου |

## 7. Η εφαρμογή Android

Δεν αποτελεί μέρος του Docker stack· εγκαθίσταται απευθείας στις συσκευές ως αρχείο APK.

**Δεν απαιτείται Google Play.** Η απευθείας εγκατάσταση υπογεγραμμένου APK — ή διανομή μέσω MDM — είναι η συνήθης πρακτική για εσωτερικά εργαλεία. Οι αναβαθμίσεις λειτουργούν κανονικά: νέο APK εγκαθίσταται πάνω από το προηγούμενο και τα δεδομένα διατηρούνται.

Ο όρος είναι ότι **κάθε έκδοση υπογράφεται με το ίδιο keystore**. Το Android απορρίπτει ενημέρωση υπογεγραμμένη με διαφορετικό κλειδί, και η μόνη διέξοδος είναι απεγκατάσταση, που χάνει τις τοπικές ρυθμίσεις.

Πρακτικά:

- Το keystore και ο κωδικός του πρέπει να φυλαχθούν μόνιμα. **Αν χαθούν, δεν είναι δυνατή καμία μελλοντική αναβάθμιση** της εγκατεστημένης εφαρμογής — ένα νέο κλειδί απαιτεί καθαρή εγκατάσταση σε κάθε συσκευή.
- Δεν καταχωρίζονται ποτέ στο αποθετήριο. Το `.gitignore` ήδη τα εξαιρεί.

### Ποιο αρχείο εγκαθίσταται

Οι εκδόσεις παράγονται ανά αρχιτεκτονική επεξεργαστή, ώστε κάθε αρχείο να είναι μικρό:

| Αρχείο | Για ποιες συσκευές |
|---|---|
| `app-arm64-v8a-release.apk` | Όλα τα σύγχρονα κινητά — **αυτό διανέμεται** |
| `app-armeabi-v7a-release.apk` | Παλαιότερες συσκευές 32 bit |
| `app-x86_64-release.apk` | Εξομοιωτές, tablet x86 |

Το `app-release.apk` περιέχει και τις τρεις αρχιτεκτονικές και εγκαθίσταται παντού, με περίπου τριπλάσιο μέγεθος.

## 8. Λίστα ελέγχου πριν την παραγωγική λειτουργία

- [ ] Υπάρχει keystore έκδοσης και έχει κρατηθεί αντίγραφό του.
- [ ] Το APK είναι υπογεγραμμένο με αυτό, όχι με το κλειδί ανάπτυξης.
- [ ] Το αρχείο ρυθμίσεων έχει παραχθεί και έχει κρατηθεί αντίγραφό του.
- [ ] Ο πρώτος λογαριασμός διαχειριστή λειτουργεί.
- [ ] Έχει ληφθεί αντίγραφο ασφαλείας **και έχει δοκιμαστεί η επαναφορά του** τουλάχιστον μία φορά.
- [ ] Υπάρχει HTTPS μπροστά από τη διαχείριση και το API.
- [ ] Έχει οριστεί χρονοπρογραμματισμός αντιγράφων και πολιτική διατήρησης.
